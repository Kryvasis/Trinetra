# Trinetra

**Trinetra** is an AI-driven multi-vendor network security compliance auditor built as a modular,
CLI-first framework for Kali Linux. It orchestrates compliance checks against network targets,
preserves session-scoped audit evidence, maintains evolving AI-assisted audit memory, and produces
standards-aligned scorecards mapped to ISO 27001, NIST 800-53, PCI-DSS, and SOC 2 controls.

The goal is not just to run checks, but to preserve audit intelligence over time: every run leaves
durable artifacts — raw evidence, structured findings, analyst memory, and machine-readable state —
so testing can be continued, queried, summarized, and reported across sessions.

## Features

- **Deterministic stat engine** — compliance tests run as standalone shell scripts
  (`stat_scripts/V-*.sh`) invoked directly; no orchestration server.
- **Decision engine** — verdicts (`PASS` / `FAIL` / `MANUAL_REVIEW` / `ERROR`) derived from
  eval methods: `grep_present`, `grep_absent`, `exit_code_zero`, `numeric_threshold`, `regex_match`.
- **Session-centric audit memory** — each session keeps immutable-ish factual history
  (session JSON), evolving analyst intelligence (brain markdown), compact execution/recommendation
  state (brain state JSON), and a tamper-evident, hash-chained `normalized_results` log.
- **AI layer with graceful degradation** — Gemini CLI for brain reasoning/queries/suggestions,
  OpenRouter (free tier) for tool-output summarization. Findings stay durable even if the
  AI providers fail.
- **Compliance scoring & reporting** — deterministic per-framework scorer plus an LLM narrative
  layer that is strictly number-validated against scorer output (template fallback on rejection).
- **Vendor connector plugins** — pluggable device communication (`VendorConnector` registry with a
  Cisco IOS proof-of-concept and a generic SSH fallback).
- **Append-only SQLite audit log** — one row per significant action, linked via per-run UUIDs to
  the tamper-evident chain hash of each session.
- **Standards-aligned scorecards** — `-agr [cert] [session]` generates cert-mode scorecards
  (`default`, `stig` — STIG cert mode is a placeholder; no STIG framework mappings exist in the compliance manifest yet).

## Requirements

- Java (JDK 17+ recommended) — `javac` / `java`
- bash, curl, jq
- Optional (for full AI behavior):
  - **Gemini CLI** configured at `~/.gemini/settings.json` (brain queries, suggestions, compression)
  - **OpenRouter API key** in `~/.trinetra/` (tool-output summarization; rate-limited free tier)
- API keys may alternatively be supplied in a gitignored `config.json` at the project root
  (`{"gemini_api_key": "...", "openrouter_api_key": "..."}`); it takes priority over env
  vars and per-user files.
- Bundled dependency: `lib/sqlite-jdbc-3.41.2.2.jar`

## Build & Install

```bash
make compile     # build Java classes to out/
make install     # install global 'trinetra' command to ~/.local/bin
make clean       # remove out/
make rebuild     # clean + compile
```

## Usage

```bash
trinetra -new <session> <target>          # create a new session
trinetra -sessions                        # list all sessions

# Stat engine
trinetra -stat run <V-XXX> <session> <target>   # run one V-code check
trinetra -stat run-all <session> <target>       # run all stat tests sequentially
trinetra -stat status <session>                 # pass/fail tally

# Audit brain (Gemini-powered, falls back to raw data if unavailable)
trinetra -mind -read <session> "query"     # query session audit memory
trinetra -mind -update <session>           # force brain/state refresh
trinetra -mind -suggest <session> "query"  # next V-code suggestion
trinetra -mind -overall "query"            # portfolio-level global summary
trinetra -mind -score <session>            # CVE/certificate scoring

# Reporting
trinetra -agr [cert] <session>             # generate scorecard (default|stig)
trinetra -compliance-score <session>       # deterministic multi-framework score
trinetra -compliance-report <session>      # scorer + validated LLM narrative

# IDE helpers & diagnostics
trinetra -ide -r <script> [args...]        # run a script
trinetra -ide -cp <source> <session>       # copy file into session artifacts
trinetra -doctor                           # system diagnostics
```

Useful options:

```bash
--dry-run                # preview V-code execution without running
--tests <a,b,c>          # restrict run-all to selected test ids
--test-file <path>       # selection from file (one id/line or comma-separated, #-comments ok)
--workers <N>            # parallel workers for run-all
--user <name>            # audit identity for this invocation (defaults to OS user)
--list-tests             # structured JSON catalog of runnable test ids
```

### Typical workflow

```bash
trinetra -new demo example.com
trinetra -stat run V-006 demo example.com      # weak TLS check
trinetra -mind -suggest demo                    # what should I test next?
trinetra -compliance-report demo               # scorecard + narrative
```

## Architecture

Four Java entry components (see `techspec.md` for detail):

| Component | Role |
|---|---|
| `src/Trinetra.java` | CLI entry point, dispatch, doctor, options parsing |
| `src/TrinetraStat.java` | Test execution + decision engine (2_static_map.json / 3_decision_engine.csv) |
| `src/TrinetraSession.java` | Session lifecycle, finding append, state refresh |
| `src/TrinetraBrain.java` | Brain markdown patch/compress, Gemini queries, suggestion engine |
| `src/TrinetraAgr.java` | Scorecard aggregation from session JSON |
| `src/TrinetraComplianceScorer.java` | Deterministic per-framework scoring (no AI) |
| `src/TrinetraNarrativeGenerator.java` | LLM narrative layer with strict number validation |
| `src/TrinetraCompliance.java` | Control-mapping manifest loader (ISO/NIST/PCI/SOC2) |
| `src/TrinetraAudit.java` | Append-only SQLite audit log |
| `src/TrinetraIde.java` | IDE helpers: run scripts, artifact copy, session listing |
| `src/TrinetraJson.java`, `src/TrinetraCommon.java` | Minimal JSON parser, shared utilities (atomic writes, shell exec, LLM clients) |
| `src/VendorConnector*.java`, `src/CiscoConnector.java`, `src/GenericSSHConnector.java` | Vendor plugin contract + registry |

Supporting assets:

- `stat_scripts/` — executable compliance test scripts (36 shipped)
- `1_classification.csv`, `2_static_map.json`, `3_decision_engine.csv` — vulnerability master list,

## Repository Layout

```text
sessions/<name>/              per-session artifacts
  <name>.json                 factual findings history
  brain_<name>.md             evolving analyst memory (+ .bak backup)
  brain_state_<name>.json     compact state: counts, suggestions, chain hash
  artifacts/                  raw outputs
brain_state.json              global cross-session activity state
trinetra_audit.db             append-only SQLite audit log

KernJC/, difuze/              bundled reference tooling
```

## Tests

```bash
make test-java    # Java suites (run against throwaway temp roots; sessions/ untouched)
make test-cpp     # Iskabon C++ suites
make test         # both
```

## Design Principles

- CLI-first and deterministic; grep-friendly, self-describing artifacts.
- Evidence first, AI second — session JSON and state JSON are authoritative; the LLM only
  summarizes, explains, compresses, and recommends.
- Every meaningful action leaves a durable artifact; nothing critical lives only in memory.
- Graceful degradation when AI providers fail.
- Minimal dependencies beyond Java, bash, curl, jq, and Gemini CLI.

## Scope Notes

Offensive exploitation is out of scope: Trinetra is a compliance auditor. The former HexStrike
pen-test orchestration engine was fully removed (v4); compliance testing runs entirely through
the stat engine.
